# Technical Test – System Analyst (Simple Flow Documentation)

This test is designed to see **how clearly you can explain a system so that a programmer understands exactly what needs to be built**.

No coding is required.

---

## 🎯 Objective

Create **simple and clear documentation** for a small application so that:

> A programmer can implement the system **without needing to ask many follow-up questions**.

We are testing:
- Clarity of explanation
- Logical thinking
- Ability to translate business needs into technical instructions

---

## 🧩 Case Study

### Simple Inventory & Sales App

A small retail store needs an application to:
- Manage products
- Track stock
- Handle sales

There are **2 user roles**:
- **Admin**: manages products and stock
- **Cashier**: performs sales transactions

---

## 🧠 Your Task

Document the system in a way that is **easy for programmers to understand and implement**.

### 1️⃣ User Roles & Permissions

Clearly explain:
- What users exist
- What each user **can and cannot do**

Example:
- Admin: create/edit/delete products, adjust stock
- Cashier: view products, create sales

---

### 2️⃣ Main Features

List the **minimum features** the system must have.

Example:
- Login
- Product list
- Add / edit product
- Sales transaction
- Stock update after sale

Keep it simple and realistic.

---

### 3️⃣ Application Flow (Most Important)

Explain the system flow **step by step**.

Write it as if you are explaining to a programmer.

Example:
1. User logs in  
2. System checks role  
3. Admin sees admin menu, cashier sees sales menu  
4. Cashier creates a sale  
5. System reduces product stock  

---

### 4️⃣ Basic Business Rules

Explain important rules that affect development.

Example:
- Stock cannot go below 0  
- Product name is required  
- Only admin can edit products  

These rules help developers avoid incorrect behavior.

---

### 5️⃣ Error & Edge Cases

Mention **at least 3 cases** developers need to handle.

Example:
- Cashier tries to sell product with insufficient stock  
- User submits empty product name  
- Two sales happen at the same time for the same product  

Explain briefly what the system should do.

---

### 6️⃣ Simple Flow Diagram (Optional but Recommended)

You may include a simple flow diagram to help visualize the system.

Accepted formats:
- Flowchart
- Sequence diagram
- Text-based diagram (Mermaid)

Clarity > visual design.
